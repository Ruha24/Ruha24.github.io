How it works

You know what’s happening with your plugin at every step.

  1. Request

    Describe the idea, the server core and version. I reply within a day.

  2. Discussion

    I clarify mechanics, commands and permissions, and we agree on scope and timeline.

  3. Development

    I build the plugin and show you intermediate versions.

  4. Delivery

    You get the .jar, configs, a command reference and the source code.

  5. Fixes

    I fix anything that doesn’t work the way we agreed.

Frequently asked questions

Didn’t find your answer? Ask on Telegram: @ruha_42

Which server cores do you support?

Bukkit, Spigot and Paper. Mention your core and server version in the request — it determines which API features are available.

What do you need from me to get started?

Describe in your own words what the plugin should do: which commands, who can use them, what players see. You don’t need a formal spec — we’ll work out the details in a conversation.

Will I own the source code?

Yes. I hand over the source code along with the .jar, so you can extend the plugin yourself or with another developer.

Can you change someone else’s plugin?

Yes, if the source code is available. First I’ll figure out how it works and tell you what can be done.
